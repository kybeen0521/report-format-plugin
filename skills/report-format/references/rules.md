# 보고서 규칙 (형식 F · 작성 W)

한 파일에 두 부를 둔다. **F 부(형식 명세)** 는 지면·블록·장 구성, **W 부(작성 규칙)** 은 문장·표·캡션·그림 파일 규칙이다. SKILL.md 의 체크리스트가 괄호로 가리키는 F1~F6, W1~W10 이 아래 절 번호다.

## F2. 문서 구조 (순서 고정)
1. **제목** - 가운데, 17 pt, 한 줄. 주제를 한 구(phrase)로. "…에 관한 보고" 같은 군더더기 없음.
2. **부제** - 가운데, 9 pt 회색. `대상 · 자료 범위 · 날짜(YYYY-MM-DD)` 를 가운뎃점(·)으로 잇는다.
3. **핵심 결과 상자** - 굵은 제목 "핵심 결과" + 불릿 3~5개. 본문을 읽지 않아도 결론과 수치가 다 들어 있게 쓴다. 문서에서 가장 먼저 보이는 요소. 문서의 유일한 상자.
4. **번호 장** `1. 제목`, 절 `1.1 제목`. 장 제목은 왼쪽 굵은 세로선 + 회색 띠, 절 제목은 굵은 글자만.
5. **부록 없음** - 부록은 두지 않는다. 용어 정의는 사용자가 요청했을 때만 본문에 쓴다(SKILL.md 내용 범위 규칙).

장 순서의 표준형(주제에 맞게 이름은 바꾸되 흐름은 유지):
```
핵심 결과(상자)
1. 자료와 문제 설정   ← 무엇을, 어떤 자료로, 왜 이 지표로
2. 방법              ← 절차 그림 1장 + 절(2.1, 2.2, …)마다 설정값 표
3. 결과              ← 큰 그림 중심, 캡션은 제목 한 줄, 해석은 본문 문단
4. (결과 2 / 불확실성 / 민감도)  ← 요약 표 + 해석 문단
5. (쟁점 검토)        ← 문제 된 자료·조건을 따로 다룸
6. 검증              ← 검증 표 + 오차의 출처 설명
7. (다음 단계)        ← 사용자가 요청했을 때만. 부록 없음
```

## F3. 블록별 규격

### 표
- 3선 표: 위 2 px, 머리글 아래 1 px, 맨 아래 2 px (#333). 행 사이 1 px #bbb. 세로선 없음.
- 8.8 pt, 셀 가운데 정렬, 머리글 배경 #fafafa, 굵기 600. 표 전체 가운데 정렬(`margin: auto`).
- **캡션은 표 아래**, 가운데, 8.8 pt 회색(#444): `**표 N.** 제목.` 제목 한 줄만 쓴다. 표를 읽는 조건(어느 평면인지, 무엇을 제외했는지)은 제목 안의 짧은 구(`(P_d 7 평면)`)나 본문 문단에 둔다.
- 위치: **그 표를 설명하는 문단 바로 다음**. 표를 문서 끝에 모으지 않는다.
- 표는 페이지 안에서 나뉘지 않는다(빌더가 표와 캡션을 한 덩어리로 둔다).
- 빈 셀은 `-` 또는 `없음`. 단위는 머리글에 `[단위]`.
- 행 수 6개 이하의 작은 표는 설명 문단과 나란히 2단(`:::two`)으로 둔다(표 1 사례).

### 그림
- 가운데 정렬, 폭은 기본 100 %; 작은 그래프는 66 %·88 % 로 줄일 수 있다. 절차도·모식도는 줄이지 않고 가로판으로 다시 그려 100 % 로 넣는다(W10).
- **캡션은 그림 아래**, 9 pt: `**그림 N.** 제목.` 제목 한 줄만 쓴다. 그림에서 무엇이 보이는지는 그림을 가리키는 본문 문단에 쓴다.
- 그림과 캡션은 같은 페이지(빌더가 한 덩어리로 둔다). 큰 그림(3장 이상 패널)은 사실상 한 쪽을 차지한다.
- 본문에서 `그림 N` 으로 먼저 언급한 뒤 그림이 나온다.
- 그림 파일 규격: PNG 160 dpi, `bbox_inches="tight", pad_inches=0.06`, 흑백·회색조, 패널 제목 `(a) …` 10 pt bold 가운데, 범례는 그래프 밖 또는 빈 칸. 패널 3장은 2 + 1 배치(윗줄 2, 아랫줄 가운데 1), 아랫줄 빈 칸에 색막대·범례.

### 강조 상자 (`:::key`)
- 1.5 px 검정 테두리, 배경 #fbfbfb, 안쪽 여백 8 pt 12 pt.
- 문서 첫머리 **핵심 결과** 에만 쓴다. 읽기·참고·주의 상자는 두지 않는다.
- 첫 줄은 `<b>제목</b>`, 이어서 불릿. 불릿 하나는 2~3문장.

### 수식
- 세리프 10.5 pt 가운데. 한 줄. 변수는 `<sub>` 로 아래첨자. 번호는 필요할 때만 오른쪽에.

### 문단
- 굵은 리드 문장으로 시작하는 문단을 허용: `**성능 지표는 등온효율**이다.`
- 한 문단 4~8문장. 숫자는 본문에 넣되, 3개 이상 나열되면 표로 뺀다.

## F4. 페이지 나눔 규칙

# W 부. 작성 규칙
F 부가 지면을 정하면, W 부는 무엇을 어떻게 쓰는지를 정한다.

## W1. 첫머리
- 제목은 명사구 하나. 부제에 대상·자료 범위·날짜.
- 핵심 결과 상자는 **결론 → 수치 → 조건·예외 → 방법의 요점** 순. 불릿마다 숫자가 하나 이상 들어간다. 여기 쓴 숫자는 본문 표의 값과 글자까지 같아야 한다.

## W2. 본문 문장
- 한글 서술체("~한다", "~이다"). 영어는 그림 라벨·변수명·고유 용어에만.
- 한 문장에 생각 하나. 접속사로 문장을 잇지 않고 끊는다.
- 주장 뒤에 근거를 같은 문단 안에 둔다(값, 그림 번호, 표 번호).
- 원인을 모르면 "원인 미확인"이라고 쓴다. 추정은 "~로 보인다"로 구분한다.
- 첫 사례·최초·유일 같은 표현을 쓰지 않는다. 의의는 기존 방법과의 차이로만 말한다.
- 숫자와 단위 사이 반 칸(`3,600 rpm`, `5 %p`). 범위는 하이픈(`1.500-2.000 %p`).
- **계산·측정값은 소수 셋째 자리까지 반올림**한다(`0.964`, `1.555 %`, `4.754 %p`). 자릿수를 값마다 달리 하지 않는다. 정수 개수(점 수, 학습점 수), 절 번호, 날짜, 설정 상수(`1.5 IQR`, 탐색 범위 `(1e-6, 0.1)`)는 예외.
- **천 단위는 쉼표**로 끊는다(`3,384 rpm`, `12,046 m³/hr`, `1,052.961 kW`, `4,331개`). 본문·표·캡션·그림 눈금·범례 모두 같다. 수식 안의 상수(`Q/3600`, `× 1000`)와 연도는 예외.
- 본문 수치는 손으로 옮겨 적지 않고 계산 결과를 변수로 넣는다. 자릿수·쉼표를 한 곳에서 바꿀 수 있고, 핵심 결과 상자와 표의 값이 어긋나지 않는다.
- 빌더가 위 두 규칙을 자동 점검해 경고를 낸다. 점검이 잘못 잡은 예외는 `<span class="nocheck">…</span>` 로 감싼다.
- em dash(U+2014)·en dash(U+2013)는 쓰지 않는다. 하이픈(-)만. 수학 마이너스(−)는 부호라 예외.
- 화살표(→)는 캡션·상자 안에서 값의 변화(`60 % → 77-88 %`)에만 허용, 본문 문장에는 쓰지 않는다.

## W3. 표
- 표는 "비교"가 목적이다. 비교 축(자료 구분, 조건)이 첫 열, 지표가 나머지 열.
- 같은 문서 안에서 같은 뜻의 열 이름은 같은 글자로(예: `자료`, `P_d`).
- 캡션은 제목 한 줄. 읽는 조건은 제목 안의 짧은 구로만. 예: `표 3. 학습된 하이퍼파라미터(P_d 7 평면).`
- 표 하나는 한 화면에 들어오는 크기(행 12개 이하). 넘치면 나눈다.
- 머리글의 아래첨자는 `<sub>` 로 쓴다(`P<sub>d</sub> 부근`, `_` 표기 금지). 머리글이 길어 두 줄이 되면 줄바꿈 위치를 `<br>` 로 직접 정한다(`등온효율<br>평균 상대 오차 [%]`). 칸 폭에 맡기는 자동 줄바꿈은 "상/대 오차"처럼 단어 중간이 끊기므로 쓰지 않는다.
- 표 안 숫자도 소수 셋째 자리·천 단위 쉼표 규칙을 따른다. 한 열 안에서 자릿수를 통일한다.

## W4. 그림 캡션
- 구조: `그림 N. [무엇을 그렸나].` 제목 한 줄만.
- 기호는 그림 안 범례·색막대로 푼다. 캡션에 기호 설명·관찰 문장을 덧붙이지 않는다.
- 그림에서 무엇이 보이는지는 그 그림을 처음 언급하는 본문 문단에 쓴다.
- 남의 자료 그림은 제목 뒤에 출처 한 줄(W10).

## W5. 결과 해석
- 읽기 상자는 두지 않는다. 결과 표의 해석이 필요하면 표를 소개하는 본문 문단에 "무엇이 보인다 → 왜 그런가" 순으로 쓴다.
- 지표의 한계는 사용자가 요청한 판단에 영향을 줄 때만 본문 한 문장으로 쓴다.

## W6. 검증 장
- 표 하나(조건별 오차)와, 오차가 **어디서** 오는지 설명하는 문단.
- 오차가 나쁜 쪽으로 변한 경우도 숨기지 않고 이유와 함께 쓴다.

## W7. 다음 단계
- 사용자가 요청했을 때만 쓴다. 요약을 반복하는 맺음말은 쓰지 않는다.
- 쓸 때는 불릿. 결정이 필요한 항목은 선택지를 괄호로(`(명시 / 표시 / 축 범위 조정)`).

## W8. 용어 설명
- 부록을 두지 않는다. 용어 정의는 사용자가 요청했을 때만 본문 문장으로 쓴다(괄호 풀이로 넣지 않는다).

## W9. 그림 파일 (matplotlib 기준)
- `color="k"` 또는 회색조, `cmap="Greys"`. 선 종류·마커로 구분.
- 패널 제목 `ax.set_title("(a) …", fontsize=10, fontweight="bold", loc="center")`.
- 축 라벨에 단위 `[ ]`. 격자는 `ls=":", lw=0.4`.
- 저장 `dpi=160, bbox_inches="tight", pad_inches=0.06`.
- 범례는 `frameon=False`, 그래프 밖 또는 빈 칸.
- 눈금·범례·주석의 숫자도 본문 규칙과 같다: 4자리 이상은 `ax.set_xticklabels([f"{v:,}" for v in ticks])` 로 쉼표, 주석 값은 `f"{v:.3f}"`. 등고선 수준값처럼 정의된 상수는 예외.
- parity plot(실측 대 예측): x 축 `measured`, y 축 `predicted`(map·model 같은 말 대신), 대각선 범례는 `ideal`.
- 상자그림: 수염은 1.5 IQR 규칙(울타리 안 마지막 값), 울타리 밖 값과 별도 최댓값 표시는 그리지 않고 수치는 본문에 적는다. 상자마다 그 상자에 속한 자료 점 수를 x 축 이름 아래 `(n pts)` 로 적되, 구간이 이어지면 하한 포함·상한 미포함(마지막 구간만 상한 포함)으로 세어 합이 전체와 같게 한다. 세로축 범위는 그린 요소(수염 끝) 최댓값에 맞추고 자료 없는 여백을 두지 않는다.
- 3D 는 격자·등고선 없이 곡면과 점만. 2D 등고선은 두 종류 이상 겹치지 않게(채움 하나 + 선 하나).

## W10. 원천 그림을 보고서판으로 옮기기
연구·개발 중에 나온 그림(그래프, 모식도, 사진, 원고·발표용 그림)은 만들어진 지면이 보고서와 다르다(2단 원고의 단 폭, 슬라이드 16:9, 세로 사진 등). 그대로 줄여 넣지 않고 아래 순서로 **보고서판**을 만든다.

**1) 원천은 건드리지 않는다.** 보고서판은 별도 파일(`이름_report.png` 등)로 만들고, 원천을 만든 스크립트의 옵션·모드로 뽑는다. 원천 파일을 덮어쓰거나 원천 스크립트의 기본 출력을 바꾸지 않는다. 원천의 도형·문구·수치가 바뀌면 보고서판도 같은 스크립트로 다시 뽑는다.

**2) 판정: 보고서 지면에 넣었을 때를 계산한다.** 본문 폭 174 mm(2단 칸 약 84 mm) × 삽입 폭 %로 실제 크기를 구하고 셋을 본다.
| 항목 | 기준 | 넘으면 |
|---|---|---|
| 좌우 빈 폭 | 본문 폭의 40 % 이하 | 가로로 다시 배치 |
| 그림 높이 | 쪽 본문 높이(257 mm)의 75 % 이하 | 배치를 바꾸거나 나눈다 |
| 그림 안 글자 | 삽입 크기에서 7.5-9 pt(캡션 9 pt 이하) | 글자 크기를 바꿔 다시 그린다 |
| 해상도 | 삽입 크기에서 150 dpi 이상 | 원천에서 다시 내보낸다(확대 금지) |
빌더가 이 기준으로 **자동 맞춤**한다(5 절). 글자 크기는 미리보기로 본다.

**3) 종류별 처리.** 비율을 맞추려고 그림을 늘이거나(가로세로 비 변경) 이미지째 확대·축소해 글자 크기를 바꾸지 않는다. 다시 그릴 수 있는 것은 다시 그리고, 다시 그릴 수 없는 것은 자르기와 묶기만 한다.
| 원천 | 보고서판 만드는 법 |
|---|---|
| 데이터 그래프(matplotlib 등) | 같은 스크립트에서 `figsize` 폭을 보고서 폭(6.9 in = 174 mm, 2단 칸 3.3 in)으로 다시 그린다. 세로 1열 패널은 가로 나란히 또는 2 + 1 로 바꾼다. W9 규격 적용 |
| 모식도·절차도(draw.io 등) | 흐름 방향을 바꿔 다시 배치한다. 세로로 이어진 단계는 단계 묶음을 가로로 나란히 두고 묶음 사이를 화살표로 잇는다. 단계 안은 세로 흐름을 유지하고, 묶음 높이를 같게 맞춘다(단계 안 화살표 길이로 조정). 모든 단계에 걸친 요소(검증 등)는 아래 전체 폭 상자로 둔다. 도형 의미와 문구는 원천과 같게 둔다. 100 % 폭으로 넣는다 |
| 사진·스크린샷·스캔(다시 그릴 수 없음) | 필요 없는 가장자리 자르기만 한다. 밝기·대비 외 보정, 합성, 지우기, 비율 변경은 하지 않는다. 세로 사진 한 장은 `:::two` 로 설명 문단 옆 칸에 둔다. 세로 사진 두세 장은 높이를 맞춰 한 줄로 묶고 `(a)`·`(b)` 패널 제목을 단다. 사진은 원래 색을 둘 수 있으나(그래프·모식도만 회색조) 캡션은 색에 기대지 않는다(흑백 인쇄 대비) |
| 원고·슬라이드용 그림 | 위 종류 중 해당하는 것으로 처리한다. 그림 라벨은 원천 언어(영어 등) 그대로 둘 수 있다(W2) |
| 남의 문헌·자료의 그림 | 자르기만 하고 캡션 끝에 출처(`자료: 저자(연도) Fig. 3`)를 적는다. 다시 그렸으면 `(… 를 바탕으로 다시 그림)` |

**4) 반영.** 보고서 원고(markdown 또는 빌드 스크립트)가 보고서판 파일을 가리키게 하고 폭은 판정에서 정한 값으로 적는다. 캡션은 보고서판 기준으로 다시 읽어, 배치가 바뀌어 틀어진 위치 표현("위", "왼쪽" 등)이 없는지 본다. 미리보기에서 그림 쪽과 그 앞 쪽의 빈 곳을 확인한다.

**5) 빌더 자동 맞춤.** `report_kit.py` 는 그림마다 아래 순서를 자동으로 밟고, 한 일은 "그림 자동 맞춤", 못 한 일은 "그림 배치 미해결"로 출력한다.
| 순서 | 조치 | 조건·한계 |
|---|---|---|
| 1 | 둘레 흰 여백을 1 % 만 남기고 자르기 | Pillow 가 있을 때. 흰색·투명 여백만 |
| 2 | 원천 재생성 | 그림에 `regen` 을 달았고 판정에 걸릴 때. 목표 크기(칸 폭 mm, 최대 높이 mm)를 넘기고, 돌아온 그림은 기록된 dpi 의 실제 크기로 넣는다 |
| 3 | 폭 조정 | 높이 한도를 넘으면 줄이고, 좌우 빈 폭이 크면 기준선(칸 폭 60 %)까지만 늘린다. 더 늘리면 그림 안 글자가 커지므로 그 이상은 재생성 몫 |
| 4 | 앞 문단 옆 배치 | 세로로 긴 그림(세로/가로 > 1.2)이 기준선보다 좁거나 쪽 절반보다 클 때, 바로 앞 블록이 문단이면 문단 왼쪽·그림 오른쪽 2단 |
| 5 | 미해결 출력 | 위로 못 고친 것(앞이 문단이 아닌 세로 그림, 해상도 부족 등). CLI 는 docx 를 쓴 뒤 종료 코드 3(`--lenient` 로 끔), API 는 `build(strict=True)` 또는 `REPORT_STRICT=1` 일 때 3 |
- 재생성 등록: markdown `{width=66% regen="python3 fig.py --w {w_mm} --h {h_mm} --out {out}"}`, Python API `r.fig(path, cap, regen=lambda w_mm, h_mm: make(w_mm, h_mm))`(새 PNG 경로를 돌려준다). 그래프 스크립트는 `figsize_mm(w_mm, h_mm)` 로 받은 크기 그대로 그린다.
- 자동 맞춤을 끄려면 `{fit=off}` 또는 `fit=False`.
- 미해결이 남으면 이 절 3) 표대로 원천을 고쳐(또는 `regen` 을 달아) 다시 빌드하고, 미해결 0건이 될 때까지 반복한다.
