# 기술 보고서 형식 (report-format)

A4 한글 기술 보고서를 일정한 형식의 **Word(.docx)** 로 만든다. 같은 원고로 PDF 도 낼 수 있다(`--format pdf`). 형식은 2026-09 산출 `report.pdf` 를 역설계한 것이며 주제·분야에 묶이지 않는다. 자료 분석, 시험 결과 정리, 방법 설명, 검토 의견 등 어떤 내용이든 이 형식으로 낸다.

## 발동 조건
- 보고서·정리 문서·결과 요약을 **Word 또는 PDF 로** 만들거나 고치는 모든 요청. 형식을 말하지 않으면 Word.
- 기존 보고서(`report.docx`, `report.pdf`)의 내용 갱신(수치·그림 교체) 요청.
- "이 형식으로", "보고서처럼 정리" 같은 형식 지정 요청.
- 논문 원고(KSFM 등)는 이 스킬이 아니라 논문 형식 스킬을 쓴다. 보고서와 논문은 형식이 다르다.

## 설치와 위치
이 폴더(`report-format/`) 하나가 스킬 전부다. 다른 프로젝트·폴더에 기대지 않는다.
- 기본 설치는 플러그인이다: `/plugin marketplace add kybeen0521/report-format-plugin` 뒤 `/plugin install report-format@report-format`. 플러그인 캐시에 설치되며 모든 프로젝트에서 쓴다.
- 플러그인 없이 쓸 때는 이 폴더를 `~/.claude/skills/report-format/`(모든 프로젝트) 또는 저장소의 `.claude/skills/report-format/`(그 저장소만)에 복사해도 같다.
- 아래 명령의 `${CLAUDE_SKILL_DIR}` 는 Claude Code 가 **이 SKILL.md 가 있는 폴더**로 치환하는 변수다. 치환되지 않는 환경이면 이 SKILL.md 가 있는 폴더 경로를 직접 넣는다. 스크립트는 폴더 안 상대 경로만 쓰므로 위치를 옮겨도 고칠 것이 없다.
- 설치 폴더는 플러그인 갱신 때 바뀔 수 있다. 내려받은 폰트·예비 venv 는 설치 폴더가 아니라 사용자 데이터 폴더에 두므로 갱신 뒤에도 남는다. 산출물(보고서·미리보기)은 설치 폴더가 아니라 원고 옆에 쓴다.
- 처음 쓰는 PC 에서는 `python3 ${CLAUDE_SKILL_DIR}/scripts/report_kit.py setup` 한 번으로 Word 빌더 `python-docx` 와 PDF 조판 엔진 `typst`(둘 다 pip 패키지, 시스템 라이브러리·관리자 권한 불필요)를 설치하고 한글 폰트 두 파일(Regular·Bold)을 사용자 데이터 폴더(`~/.local/share/report-format/fonts`, Windows 는 `%LOCALAPPDATA%\report-format\fonts`)에 내려받는다. 플러그인을 갱신해도 남는다. Windows·macOS·Linux 모두 같다.

## 절차 (순서대로)

### 0단계: 환경 점검
```
python3 ${CLAUDE_SKILL_DIR}/scripts/report_kit.py doctor --build
```
"준비됨" 이 아니면 `setup` 을 먼저 돌린다. `--build` 는 예제 보고서를 임시 폴더에 Word·PDF 로 실제로 만들어 보고, Word 미리보기 엔진(설치된 Microsoft Word 또는 LibreOffice)이 docx 를 PDF 로 바꿀 수 있는지 확인한다. 이 단계는 PC 마다 한 번이면 된다.

### 1단계: 규칙 로드
`references/rules.md`(F 부 지면·블록·장 구성, W 부 문장·표·캡션·그림 규칙)와 이 파일의 **보고서 내용 범위 규칙** 절을 **작성 전에** 읽는다. 기억에 의존하지 않고 매번 읽는다. 검수 항목은 이 파일 끝의 체크리스트다.

### 2단계: 구성 잡기
문서 구조는 고정이다.
```
제목 / 부제(대상 · 자료 범위 · 날짜)
핵심 결과 상자 (불릿 3~5, 수치 포함)
1. 자료와 문제 설정 (작은 표는 문단 옆 2단)
2. 방법 (절차 그림 + 절마다 설정 표)
3. 결과 (큰 그림, 제목 한 줄 캡션)
4. 요약 지표 (표, 해석은 본문 문단으로)
5. 쟁점 검토 (있을 때)
6. 검증 (표 + 오차 출처)
7. 다음 단계 (사용자가 요청했을 때만)
```
부록은 쓰지 않는다. 용어 정의·배경 설명은 사용자가 요청했을 때만 본문에 쓴다(내용 범위 규칙).
장 이름은 주제에 맞게 바꾸되 흐름(결론 먼저 → 자료 → 방법 → 결과 → 해석 → 검증)은 유지한다. 요청 항목에 없는 장은 뺀다. 장을 빼도 순서는 바꾸지 않는다.

### 3단계: 그림 준비
`rules.md` W9 절 규격으로 그림 PNG 를 만든다(회색조, 160 dpi, pad 0.06 in, 패널 제목 `(a)` bold, 범례 밖). 패널 3장은 2 + 1 배치. 그림은 본문에서 먼저 언급한 뒤 배치한다.

연구·개발 중에 이미 나온 그림(원고 단 폭 그림, 슬라이드 그림, 세로 사진, 스크린샷 등)을 쓸 때는 `rules.md` **W10** 절대로 **보고서판**을 따로 만든다.
- 원천 파일은 그대로 두고, 같은 스크립트의 옵션·모드로 별도 파일을 뽑는다.
- 보고서 지면(본문 폭 174 mm, 2단 칸 약 84 mm)에 넣었을 때의 좌우 빈 폭·높이·해상도로 판정한다.
- 다시 그릴 수 있는 것(그래프·모식도)은 보고서 폭으로 다시 배치하고, 다시 그릴 수 없는 것(사진)은 자르기·묶기·`:::two` 로만 맞춘다. 늘이기·이미지째 확대는 하지 않는다.
- 빌더가 흰 여백 자르기·폭 조정·앞 문단 옆 배치를 자동으로 하고, 그림에 `regen`(재생성 명령·함수)을 달아 두면 판정에 걸릴 때 보고서 크기로 다시 그리게 한다. 원천 스크립트가 있는 그림은 `regen` 을 다는 것을 기본으로 한다.

### 4단계: 원고 작성
markdown 파일 하나에 쓴다. 문법은 `scripts/report_kit.py` 머리 주석과 `examples/example_report.md` 참조.
- 머리말 `title / subtitle / output`(output 은 파일 이름. 확장자는 형식에 맞게 바뀐다).
- `:::key 핵심 결과` … `:::` 상자, `:::two` … `|||` … `:::` 2단.
- 표는 파이프 표 + **바로 다음 줄** `표 N. 캡션.` (캡션은 표 아래에 놓인다).
- 그림은 `![그림 N. 캡션](path){width=66%}`.
- 수식은 `$$ … $$` 한 줄(`<sub>`·`<sup>` 허용).
- 굵은 리드는 `**지표는 등온효율**이다.` 처럼 문단 첫머리에. 문단 사이는 빈 줄.
- 계산 결과가 스크립트에서 나오면 Python API(`Report` 클래스)로 같은 형식을 만든다. 표 값은 코드가 채우고 손으로 옮기지 않는다.

### 5단계: 빌드와 미리보기
```
python3 ${CLAUDE_SKILL_DIR}/scripts/report_kit.py build 원고.md --preview              # Word(.docx), 기본
python3 ${CLAUDE_SKILL_DIR}/scripts/report_kit.py build 원고.md --format pdf --preview # PDF
```
- 형식은 `--format` → `-o` 의 확장자(`.pdf`/`.docx`) → Word 순으로 정한다. 사용자가 PDF 를 말하지 않으면 Word 로 낸다.
- Word 글꼴은 **맑은 고딕**(Windows 기본 글꼴이라 받는 PC 에서도 같다). 그림은 docx 안에 들어가고 지면 값(여백·크기·3선 표·장 띠·상자)은 PDF 와 같다.
- Word 미리보기는 설치된 Microsoft Word(Windows, 또는 WSL 에서 Windows 의 Word) → LibreOffice 순으로 docx 를 PDF 로 바꿔 쪽 PNG 를 만든다. 실제 Word 쪽 나눔 그대로다. 둘 다 없으면 typst 근사 미리보기로 대신하고 경고를 낸다(쪽 나눔이 Word 와 다를 수 있다). 이미 만든 docx 는 `report_kit.py preview 보고서.docx` 로 다시 볼 수 있다.
- PDF 폰트는 `--font` → `REPORT_FONT` 환경변수 → `fonts/`(스킬 폴더 안) → 사용자 데이터 폴더 → 사용자·시스템 폰트 폴더 순으로 정적 Noto Sans KR Regular·Bold 한 쌍을 찾는다. 시스템 글꼴은 조판에 쓰지 않으므로 PC 가 달라도 출력이 같다. 수식 세리프는 typst 내장 Libertinus.
- `--typ 파일.typ` 를 주면 생성된 typst 원본을 남긴다(PDF 배치 문제를 손으로 살필 때).
- Python API 를 쓸 때는 `sys.path.insert(0, "${CLAUDE_SKILL_DIR}/scripts")` 뒤 `from report_kit import Report, num`.
- `--preview` 가 만든 `*_preview/sheet*.png`(4쪽씩 접촉 시트, 쪽별은 `p01.png` …) 를 **반드시 Read 로 열어** 배치를 눈으로 확인한다: 표가 설명 문단 바로 아래에 있는가, 그림·캡션이 같은 쪽에 있는가, 장 제목이 쪽 맨 아래에 홀로 남지 않았는가, 큰 그림 앞 쪽이 지나치게 비지 않았는가.
- 빌더가 "그림 자동 맞춤"(한 일)과 "그림 배치 미해결"(못 한 일)을 출력한다. 미해결이 있으면 파일은 써지지만 종료 코드 3 이다. 미해결마다 W10 3) 표대로 원천을 고치거나 `regen` 을 달아 다시 빌드하고, **미해결 0건이 될 때까지 반복**한다. 자동 맞춤 기록도 미리보기로 결과를 눈으로 확인한다.
- 빌더가 em/en dash 를 발견하면 경고를 낸다. 하이픈으로 고치고 다시 빌드한다.
- 빌더가 "숫자 표기 점검" 경고(소수 셋째 자리 아님, 천 단위 쉼표 없음)를 내면 값을 고치고 다시 빌드한다. 점검이 잘못 잡은 예외(설정 상수 등)만 `<span class="nocheck">…</span>` 로 감싼다.
- 미리보기 폴더는 산출물이 아니다. 확인 후 지운다.

### 6단계: 검수와 보고
**내용 범위 규칙**의 작성 후 점검을 먼저 하고, 아래 **검수 체크리스트** 항목마다 ✅/❌/N/A 를 붙여 보고한다. ❌ 는 고친 뒤 재검한다. 보고에는 쪽수, 표·그림 수, 미리보기에서 확인한 배치 문제와 조치를 적는다.

## 보고서 내용 범위 규칙
이 절은 내용(무엇을 쓰는가)만 정한다. 양식·폰트·레이아웃은 위아래 다른 절과 `references/rules.md` F 부를 따른다. 다른 절이나 `rules.md` 와 겹치면 이 절이 우선한다.

[금지 요소]
1. 본문보다 흐리거나 작은 회색 글씨로 쓰는 보조 문장 (부연 설명, 주석, 설명용 서브타이틀, 표나 그림 아래의 해설)
2. "참고", "Note", "Tip", "주의" 같은 별도 박스나 콜아웃
3. 각주, 출처 외의 꼬리말, 요약을 반복하는 맺음말
4. 요청하지 않은 배경 설명, 일반론, 용어 정의, 향후 과제 제안
5. 위 1번을 괄호 문장이나 작은 글씨로 바꿔 다시 넣는 것

[허용 요소]
1. 표와 그림에는 제목 한 줄만 단다. 해설은 넣지 않는다.
2. 출처가 꼭 필요하면 한 줄로만 표기한다.
3. 본문은 사용자가 요청한 항목과 그 근거만 쓴다.

[작성 후 점검]
결과물을 내기 전에 위 금지 요소가 있는지 확인하고, 있으면 삭제한 뒤 출력한다.
삭제해서 정보가 빠진다면 본문에 넣을 가치가 있는지 판단해 본문 문장으로 옮기거나 버린다.

[적용 범위]
- 부제(`대상 · 자료 범위 · 날짜`)와 쪽번호는 양식 요소라 금지 1번에 들지 않는다. 부제에 설명 문장은 넣지 않는다.
- 첫머리 **핵심 결과** 상자는 결론 요약 블록이라 금지 2번의 콜아웃이 아니다. 그 밖의 상자(읽기, 참고 등)는 두지 않는다.
- 다음 단계·향후 과제, 용어 풀이, 배경 장은 사용자가 요청했을 때만 쓴다.

## 강제 규칙 요약 (세부는 references/rules.md)
- 첫 쪽 첫 요소는 **핵심 결과 상자**. 상자의 수치는 본문 표와 글자까지 같다.
- 표 캡션은 **표 아래**, 그림 캡션은 **그림 아래**. 둘 다 가운데.
- 표는 설명 문단 **바로 다음**. 문서 끝에 모으지 않는다.
- 캡션은 **제목 한 줄**. 해설·관찰 문장은 캡션에 넣지 않고 필요하면 본문 문단에 쓴다. 출처가 꼭 필요하면 한 줄.
- 상자는 첫머리 **핵심 결과** 하나뿐. 읽기·참고·주의 상자는 두지 않는다.
- 회색조 그림, 세로선 없는 3선 표, 장식은 세로선·회색 띠뿐.
- em dash·en dash 금지, 하이픈만. 숫자와 단위 사이 반 칸. 첫 사례·최초 표현 금지.
- 계산·측정값은 **소수 셋째 자리까지 반올림**, 4자리 이상은 **천 단위 쉼표**(`3,384 rpm`). 본문·표·캡션·그림 눈금이 모두 같다. 빌더가 자동 점검해 경고를 낸다.
- 표 머리글 첨자는 `<sub>`, 두 줄 머리글은 `<br>` 로 직접 나눈다. 자동 줄바꿈으로 단어가 끊기게 두지 않는다.
- **부록은 쓰지 않는다**. 다음 단계·용어 정의·배경은 사용자가 요청했을 때만.

- `SKILL.md` - 절차·내용 범위 규칙·강제 규칙·검수 체크리스트(이 파일)
- `references/rules.md` - F 부 형식 명세(지면·블록·장 구성), W 부 작성 규칙(문장·표·캡션·그림 파일, 원천 그림의 보고서판 W10)
- `scripts/report_kit.py` - markdown/Python → Word(.docx, python-docx) 또는 typst → PDF, Word·typst 미리보기 PNG, 금지 문자·숫자 표기·그림 배치 검사, `doctor`/`setup`. 지면 스타일(Word 는 `_Docx`, PDF 는 typst 전문)도 이 안에 있다
- `examples/example_report.md`, `examples/make_example_figs.py` - markdown 문법의 살아 있는 예제. `doctor --build` 가 이 둘로 자기 검증한다
- `fonts/` - (선택, PDF 용) 폴더째 복사할 때 폰트를 같이 넣는 자리(git 제외). 없으면 `setup` 이 사용자 데이터 폴더에 받는다

## 의존성
사람이 갖출 것은 Python 3 뿐이다. Word 는 pip 패키지 `python-docx`, PDF 는 `typst` 가 맡고, 시스템 라이브러리나 관리자 권한은 필요 없다. Word 미리보기는 PC 에 있는 Microsoft Word 또는 LibreOffice 를 쓰고, 없으면 typst 근사 미리보기로 대신한다. `matplotlib` 은 그림 스크립트를 돌릴 때만, `Pillow`·`PyMuPDF` 는 그림 여백 자르기·미리보기에 쓰는 선택 사항이다. `report_kit.py setup` 이 python-docx·typst 와 폰트를 준비한다.

## 검수 체크리스트
빌드 후 미리보기(`*_preview/sheet*.png`, Word 산출물은 Word 렌더)를 보며 항목마다 ✅/❌/N/A 를 붙여 보고한다. ❌ 는 고치고 재검한다. 괄호는 `references/rules.md` 의 절 번호(F 부·W 부).

### A. 첫머리 (F2, W1)
- [ ] A1 제목이 명사구 한 줄, 가운데 정렬
- [ ] A2 부제가 `대상 · 자료 범위 · YYYY-MM-DD` 형식
- [ ] A3 첫 쪽 첫 요소가 핵심 결과 상자이고 불릿 3~5개, 불릿마다 수치가 있다
- [ ] A4 상자의 수치가 본문 표·문장의 값과 글자까지 같다

### B. 장 구성 (F2)
- [ ] B1 장 번호 `1.`, 절 `1.1`. 부록 없음
- [ ] B2 흐름이 자료 → 방법 → 결과 → 해석 → (검토) → 검증 순이고, 요청 항목에 없는 장이 없다
- [ ] B3 다음 단계·향후 과제 장은 사용자가 요청했을 때만 있다
- [ ] B4 부록이 없고, 용어 정의·배경 설명은 사용자가 요청했을 때만 있다

### C. 표 (F3, W3)
- [ ] C1 3선 표(세로선 없음), 셀 가운데, 단위는 머리글 `[ ]`
- [ ] C2 캡션이 **표 아래** `표 N. 제목` 한 줄이고 해설 문장이 없다
- [ ] C3 표가 그 표를 설명하는 문단 바로 다음에 있다(미리보기로 확인)
- [ ] C4 작은 표(행 6 이하)는 문단 옆 2단에 두었다(해당 시)
- [ ] C5 표가 쪽 사이에서 나뉘지 않았다
- [ ] C6 표 번호가 본문 등장 순서와 같고 본문에서 `표 N` 으로 언급된다
- [ ] C7 머리글 첨자는 `<sub>`, 두 줄 머리글은 `<br>` 로 위치를 정했고 단어 중간 끊김("상/대 오차")이 없다

### D. 그림 (F3, W4, W9)
- [ ] D1 회색조, 패널 제목 `(a)` bold, 범례가 그래프 밖, 축 라벨에 단위
- [ ] D2 캡션이 **그림 아래** `그림 N. 제목` 한 줄이고 해설·관찰 문장이 없다(출처가 필요하면 한 줄)
- [ ] D3 그림과 캡션이 같은 쪽에 있다
- [ ] D4 본문에서 `그림 N` 을 먼저 언급한 뒤 그림이 나온다
- [ ] D5 패널 3장은 2 + 1 배치, 빈 칸에 색막대·범례
- [ ] D6 눈금·범례·주석 숫자가 본문 규칙(천 단위 쉼표, 소수 셋째 자리)과 같다
- [ ] D7 parity plot 은 measured / predicted / ideal, 상자그림은 최댓값 표시 없음·상자별 `(n pts)`·수염 끝 기준 세로축(해당 시)
- [ ] D8 원천 그림을 쓴 경우 보고서판을 별도 파일로 만들었고(원천 미수정), 빌더 "그림 배치 미해결"이 0건이며 자동 맞춤 결과를 미리보기로 확인했다(W10)
